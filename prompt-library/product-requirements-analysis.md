# 产品需求分析提示词

## 需求收集与分析

### 用户需求访谈
```
你是一位资深产品经理，请进行用户需求访谈：

【访谈目标】
1. 了解用户痛点和核心诉求
2. 明确业务场景和使用流程
3. 识别目标用户群体
4. 挖掘潜在需求

【访谈提纲】
1. 背景信息
   - 您的职业/角色是什么？
   - 您目前使用什么工具/系统完成工作？
   - 日常工作中遇到的最大挑战是什么？

2. 痛点分析
   - 现有方案有哪些不满意的地方？
   - 哪些问题最常出现？
   - 解决这些问题能带来什么价值？

3. 功能期望
   - 您最希望解决的核心问题是什么？
   - 您认为最重要的功能有哪些？
   - 您对系统的期望是什么？

4. 使用场景
   - 您会在什么场景下使用这个功能？
   - 使用的频率如何？
   - 谁会参与使用这个过程？

5. 优先级排序
   - 如果只能实现一个功能，您选择哪个？
   - 哪些功能是必须有（Must have）？
   - 哪些功能是锦上添花（Nice to have）？

【输出物】
1. 用户画像（Persona）
2. 用户体验地图（User Journey Map）
3. 需求清单
4. 优先级矩阵

请进行访谈：[具体项目背景]
```

### 用户故事地图
```
请创建用户故事地图（User Story Mapping）：

【方法论】
用户故事 = 角色 + 活动 + 价值

【格式】
As a [角色], I want to [活动], so that [价值]

【地图结构】
1. 骨干（Backbone）
   - 用户主要活动（按时间顺序）
   
2. 行走骨架（Walking Skeleton）
   - MVP 必需的故事
   
3. 身体（Body）
   - 增强功能
   - 可选功能

【示例 - 电商系统】
```
用户旅程：浏览商品 → 加入购物车 → 下单 → 支付 → 收货 → 评价

骨干任务：
1. 浏览商品
   - 作为用户，我想搜索商品，以便快速找到想要的商品
   - 作为用户，我想筛选商品，以便缩小选择范围
   - 作为用户，我想查看商品详情，以便了解商品信息

2. 加入购物车
   - 作为用户，我想添加商品到购物车，以便批量购买
   - 作为用户，我想修改购物车数量，以便调整购买计划

3. 下单
   - 作为用户，我想选择收货地址，以便配送到指定地点
   - 作为用户，我想选择支付方式，以便使用偏好的支付方式

4. 支付
   - 作为用户，我想在线支付，以便快速完成订单
   - 作为用户，我想查看支付结果，以便确认支付状态

5. 收货
   - 作为用户，我想查看物流信息，以便了解配送进度
   - 作为用户，我想确认收货，以便完成交易

6. 评价
   - 作为用户，我想对商品评价，以便分享购物体验
   - 作为用户，我想晒图评价，以便更直观展示商品
```

【优先级标注】
P0：MVP 必需（没有无法上线）
P1：重要功能（应该要有）
P2：优化功能（有了更好）
P3：可有可无（时间充裕再做）

请创建：[具体产品的用户故事地图]
```

### 需求优先级管理
```
请管理需求优先级：

【优先级框架】
1. MoSCoW 法则
   - Must have（必须有）
   - Should have（应该有）
   - Could have（可以有）
   - Won't have（暂不需要）

2. RICE 评分
   - Reach（覆盖范围）
   - Impact（影响力）
   - Confidence（信心指数）
   - Effort（工作量）
   Score = (R × I × C) / E

3. Kano 模型
   - 基本型需求（Must-be）
   - 期望型需求（One-dimensional）
   - 兴奋型需求（Attractive）
   - 无差异需求（Indifferent）

【优先级调整因素】
1. 业务价值变化
2. 技术依赖关系
3. 资源约束
4. 时间窗口
5. 风险因素

【优先级矩阵】
纵轴：业务价值
横轴：实现难度
第一象限（高价值低难度）：优先做
第二象限（高价值高难度）：规划做
第三象限（低价值低难度）：空闲时做
第四象限（低价值高难度）：不做

请排序：[具体需求列表]
```

   - 转化路径
