## 1. 为什么需要分布式 ID？

### 传统自增 ID 的问题

#### 单机场景（没问题）

```sql
CREATE TABLE users (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50)
);

INSERT INTO users (username) VALUES ('张三');  -- id = 1
INSERT INTO users (username) VALUES ('李四');  -- id = 2
```

**优点：** 简单、有序、性能好

---

#### 分布式场景（问题多多）

**问题 1：分库分表 ID 冲突**

```
数据库 A          数据库 B
┌──────┐         ┌──────┐
│ id=1 │         │ id=1 │  ← 冲突！
│ id=2 │         │ id=2 │
└──────┘         └──────┘

合并数据时无法区分来源
```

**问题 2：微服务架构 ID 重复**

```
订单服务 (id=100)     支付服务 (id=100)
     ↓                      ↓
   全局唯一？              ❌ 重复！
```

**问题 3：数据迁移冲突**

```
生产环境 (id=1001)  →  测试环境 (id=1001)
                        ❌ 数据覆盖！
```

---

### 分布式 ID 的要求

| 特性 | 说明 | 重要性 |
|------|------|--------|
| **全局唯一** | 任何情况下都不重复 | ⭐⭐⭐⭐⭐ |
| **趋势递增** | 大致有序，有利于索引 | ⭐⭐⭐⭐ |
| **信息安全** | 不暴露业务信息 | ⭐⭐⭐ |
| **高性能** | 生成速度快 | ⭐⭐⭐⭐⭐ |
| **高可用** | 不依赖单一节点 | ⭐⭐⭐⭐ |

## 2. 雪花算法原理

### 什么是雪花算法？

**Snowflake** 是 Twitter 开源的分布式 ID 生成算法，生成的 ID 是一个 64 位的 Long 类型数字。

### ID 结构

```
64 位 ID 结构：

0 - 0000000000 0000000000 0000000000 0000000000 0 - 00000 - 00000 - 000000000000
│  └────────────────────┬─────────────────────┘ │   │       │   └──────┬──────┘
│                       │                       │   │       │          │
符号位              时间戳(41位)              保留  机器ID  序列号
(1位)             (毫秒级，69年)            (10位)  (5位)  (12位)
                                                          (每毫秒4096个)
```

**详细说明：**

| 部分 | 位数 | 说明 |
|------|------|------|
| **符号位** | 1 bit | 固定为 0，表示正数 |
| **时间戳** | 41 bits | 毫秒级时间差，可使用 69 年 |
| **机器 ID** | 10 bits | 最多 1024 个节点 |
| **序列号** | 12 bits | 每毫秒可生成 4096 个 ID |

**计算：**
- 时间范围：2^41 / (1000 * 60 * 60 * 24 * 365) ≈ 69 年
- 机器数量：2^10 = 1024 台
- 每毫秒 ID 数：2^12 = 4096 个
- 每秒 ID 数：4096 * 1000 = 409.6 万个

---

### 工作原理

```java
// 伪代码
public long nextId() {
    long timestamp = currentTimeMillis();
    
    // 1. 时钟回拨检测
    if (timestamp < lastTimestamp) {
        throw new RuntimeException("时钟回拨");
    }
    
    // 2. 同一毫秒内，序列号递增
    if (timestamp == lastTimestamp) {
        sequence = (sequence + 1) & MAX_SEQUENCE;
        
        // 序列号溢出，等待下一毫秒
        if (sequence == 0) {
            timestamp = waitNextMillis(lastTimestamp);
        }
    } else {
        // 3. 不同毫秒，序列号重置为 0
        sequence = 0;
    }
    
    lastTimestamp = timestamp;
    
    // 4. 组合 ID
    return ((timestamp - EPOCH) << TIMESTAMP_SHIFT) |
           (datacenterId << DATACENTER_SHIFT) |
           (workerId << WORKER_SHIFT) |
           sequence;
}
```

**核心逻辑：**
1. 获取当前时间戳
2. 如果和上次相同，序列号 +1
3. 如果序列号溢出，等待下一毫秒
4. 如果时间不同，序列号重置为 0
5. 组合时间戳、机器 ID、序列号生成最终 ID

---

### 特点

✅ **优点：**
- 全局唯一
- 趋势递增（有利于数据库索引）
- 高性能（本地生成，无网络开销）
- 不依赖第三方服务
- ID 中不包含敏感信息

❌ **缺点：**
- 依赖系统时钟（时钟回拨问题）
- 需要配置机器 ID（分布式环境下）
- ID 较长（64 位，前端可能精度丢失）

```sql
CREATE TABLE id_generator (
    id BIGINT PRIMARY KEY AUTO_INCREMENT
```

```sql
UPDATE id_generator SET id = LAST_INSERT_ID(id + 100);

-- 返回起始 ID，应用层自行分配 100 个 ID
```

**适用场景：** 单机应用、对性能要求不高的场景

#### 3.5 美团 Leaf

**两种模式：**

1. **Leaf-segment（号段模式）**
   - 从数据库批量获取号段
   - 应用层在内存中分配
   - 性能高，但有短暂不一致风险

2. **Leaf-snowflake（雪花模式）**
   - 基于雪花算法
   - 使用 ZK 管理机器 ID
   - 解决了时钟回拨问题

**优点：**
- ✅ 高性能
- ✅ 高可用
- ✅ 监控完善

**缺点：**
- ❌ 部署复杂
- ❌ 依赖中间件（DB/ZK）

**适用场景：** 大型企业、高并发场景

## 4. Java 实现雪花算法

### 4.1 基础实现

```java
/**
 * 雪花算法 ID 生成器
 */
public class SnowflakeIdGenerator {
    
    // ============================== 字段 ==============================
    
    /** 开始时间戳 (2024-01-01 00:00:00) */
    private final long epoch = 1704067200000L;
    
    /** 机器 ID 所占位数 */
    private final long workerIdBits = 5L;
    
    /** 数据中心 ID 所占位数 */
    private final long datacenterIdBits = 5L;
    
    /** 序列号所占位数 */
    private final long sequenceBits = 12L;
    
    /** 最大机器 ID (0-31) */
    private final long maxWorkerId = ~(-1L << workerIdBits);
    
    /** 最大数据中心 ID (0-31) */
    private final long maxDatacenterId = ~(-1L << datacenterIdBits);
    
    /** 序列号掩码 (0-4095) */
    private final long sequenceMask = ~(-1L << sequenceBits);
    
    /** 机器 ID 左移位数 */
    private final long workerIdShift = sequenceBits;
    
    /** 数据中心 ID 左移位数 */
    private final long datacenterIdShift = sequenceBits + workerIdBits;
    
    /** 时间戳左移位数 */
    private final long timestampLeftShift = sequenceBits + workerIdBits + datacenterIdBits;
    
    /** 上次生成 ID 的时间戳 */
    private long lastTimestamp = -1L;
    
    /** 当前毫秒内的序列号 */
    private long sequence = 0L;
    
    /** 数据中心 ID (0-31) */
    private final long datacenterId;
    
    /** 机器 ID (0-31) */
    private final long workerId;
    
    // ============================== 构造方法 ==============================
    
    public SnowflakeIdGenerator(long workerId, long datacenterId) {
        // 校验机器 ID 和数据中心 ID
        if (workerId > maxWorkerId || workerId < 0) {
            throw new IllegalArgumentException(
                String.format("Worker ID 必须在 0-%d 之间", maxWorkerId));
        }
        if (datacenterId > maxDatacenterId || datacenterId < 0) {
            throw new IllegalArgumentException(
                String.format("Datacenter ID 必须在 0-%d 之间", maxDatacenterId));
        }
        
        this.workerId = workerId;
        this.datacenterId = datacenterId;
    }
    
    // ============================== 核心方法 ==============================
    
    /**
     * 生成下一个 ID（线程安全）
     */
    public synchronized long nextId() {
        long timestamp = System.currentTimeMillis();
        
        // 1. 时钟回拨检测
        if (timestamp < lastTimestamp) {
            throw new RuntimeException(
                String.format("时钟回拨 %d 毫秒", lastTimestamp - timestamp));
        }
        
        // 2. 同一毫秒内，序列号递增
        if (timestamp == lastTimestamp) {
            sequence = (sequence + 1) & sequenceMask;
            
            // 序列号溢出，等待下一毫秒
            if (sequence == 0) {
                timestamp = waitNextMillis(lastTimestamp);
            }
        } else {
            // 3. 不同毫秒，序列号重置为 0
            sequence = 0L;
        }
        
        lastTimestamp = timestamp;
        
        // 4. 组合 ID
        return ((timestamp - epoch) << timestampLeftShift) |
               (datacenterId << datacenterIdShift) |
               (workerId << workerIdShift) |
               sequence;
    }
    
    /**
     * 等待下一毫秒
     */
    private long waitNextMillis(long lastTimestamp) {
        long timestamp = System.currentTimeMillis();
        while (timestamp <= lastTimestamp) {
            timestamp = System.currentTimeMillis();
        }
        return timestamp;
    }
    
    // ============================== 解析方法 ==============================
    
    /**
     * 从 ID 中解析时间戳
     */
    public long parseTimestamp(long id) {
        return ((id >> timestampLeftShift) & ~(-1L << 41)) + epoch;
    }
    
    /**
     * 从 ID 中解析数据中心 ID
     */
    public long parseDatacenterId(long id) {
        return (id >> datacenterIdShift) & ~(-1L << datacenterIdBits);
    }
    
    /**
     * 从 ID 中解析机器 ID
     */
    public long parseWorkerId(long id) {
        return (id >> workerIdShift) & ~(-1L << workerIdBits);
    }
    
    /**
     * 从 ID 中解析序列号
     */
    public long parseSequence(long id) {
        return id & sequenceMask;
    }
}
```

### 4.3 时钟回拨处理

**问题：** 系统时钟被手动调整或 NTP 同步导致时间回拨

**解决方案 1：等待策略（已实现）**

```java
if (timestamp < lastTimestamp) {
    // 等待时钟追上
    while (timestamp < lastTimestamp) {
        timestamp = System.currentTimeMillis();
    }
}
```

**解决方案 2：抛出异常**

```java
if (timestamp < lastTimestamp) {
    long offset = lastTimestamp - timestamp;
    if (offset <= 5) {
        // 小幅度回拨，等待
        Thread.sleep(offset * 2);
    } else {
        // 大幅度回拨，抛出异常
        throw new RuntimeException("时钟回拨过大：" + offset + "ms");
    }
}
```

**解决方案 3：使用备用机器 ID**

```java
public class AdvancedSnowflakeIdGenerator {
    
    private final SnowflakeIdGenerator primary;
    private final SnowflakeIdGenerator backup;
    private boolean useBackup = false;
    
    public synchronized long nextId() {
        try {
            if (useBackup) {
                return backup.nextId();
            }
            return primary.nextId();
        } catch (RuntimeException e) {
            // 主生成器失败，切换到备用
            useBackup = true;
            return backup.nextId();
        }
    }
}
```

```java
/**
 * 基于 ThreadLocal 的高性能雪花算法（无锁）
 */
public class HighPerformanceSnowflake {
    
    private static final ThreadLocal<SnowflakeIdGenerator> localGenerator = 
        ThreadLocal.withInitial(() -> {
            // 每个线程独立的生成器
            long workerId = getWorkerIdFromThread();
            return new SnowflakeIdGenerator(workerId, 0);
        });
    
    public static long nextId() {
        return localGenerator.get().nextId();
    }
    
    private static long getWorkerIdFromThread() {
        // 根据线程 ID 或其他标识分配 workerId
        return Thread.currentThread().getId() % 32;
    }
}
```

### 案例 2：分库分表场景

#### 需求

- 用户表按 user_id 分 16 库
- 订单表按 order_id 分 64 表
- 要求：ID 中包含分片信息

#### 实现

```java
/**
 * 带分片信息的雪花算法
 */
public class ShardedSnowflakeIdGenerator {
    
    private final SnowflakeIdGenerator baseGenerator;
    private final int shardCount;
    
    public ShardedSnowflakeIdGenerator(long workerId, long datacenterId, int shardCount) {
        this.baseGenerator = new SnowflakeIdGenerator(workerId, datacenterId);
        this.shardCount = shardCount;
    }
    
    /**
     * 生成带分片信息的 ID
     * 
     * ID 结构：
     * 高位：雪花算法 ID
     * 低位：分片编号
     */
    public long nextIdWithShard() {
        long baseId = baseGenerator.nextId();
        
        // 将分片信息编码到 ID 中
        // 方法 1：取模（简单但分布不均）
        long shardId = baseId % shardCount;
        
        // 方法 2：显式编码（推荐）
        // 假设用最后 6 位存储分片 ID（支持 64 个分片）
        long shardBits = 6;
        long shardMask = (1L << shardBits) - 1;
        
        // 确保分片 ID 在范围内
        shardId = shardId & shardMask;
        
        // 组合：高位是雪花 ID，低位是分片 ID
        return (baseId << shardBits) | shardId;
    }
    
    /**
     * 从 ID 中提取分片编号
     */
    public long getShardId(long id) {
        long shardBits = 6;
        long shardMask = (1L << shardBits) - 1;
        return id & shardMask;
    }
    
    /**
     * 从 ID 中提取原始雪花 ID
     */
    public long getBaseId(long id) {
        long shardBits = 6;
        return id >> shardBits;
    }
}
```

**使用：**

```java
// 生成分片 ID
long orderId = shardedGenerator.nextIdWithShard();

// 计算分片

// 路由到对应的表
```

### 案例 3：前端精度问题处理

#### 解决方案

**方案 1：后端返回字符串**

```java
@Data
```

```java
@Component
public class WorkerIdAllocator {
    
    @Autowired
    private CuratorFramework zkClient;
    
    public long allocateWorkerId() {
        try {
            // 在 ZK 中创建临时顺序节点
            String path = zkClient.create()
                .creatingParentsIfNeeded()
                .withMode(CreateMode.EPHEMERAL_SEQUENTIAL)

        } catch (Exception e) {

        }
    }
}
```

### Q3: 性能如何优化？

**优化 1：批量预生成**

```java
@Component
public class BatchIdGenerator {
    
    private final SnowflakeIdGenerator baseGenerator;
    private final BlockingQueue<Long> idQueue;
    
    public BatchIdGenerator() {
        this.baseGenerator = new SnowflakeIdGenerator(1, 0);
        this.idQueue = new ArrayBlockingQueue<>(1000);
        
        // 后台线程预生成 ID
        startPreGenerateThread();
    }
    
    private void startPreGenerateThread() {
        new Thread(() -> {
            while (true) {
                try {
                    if (idQueue.size() < 500) {
                        idQueue.put(baseGenerator.nextId());
                    }
                    Thread.sleep(1);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                    break;
                }
            }
        }, "id-pre-generator").start();
    }
    
    public long nextId() throws InterruptedException {
        return idQueue.take();
    }
}
```

### Q4: 如何保证高可用？

**方案 1：多节点部署**

```
节点 1 (workerId=1)  →  负载均衡  →  客户端
节点 2 (workerId=2)  →            →
节点 3 (workerId=3)  →            →

任何一个节点挂了，其他节点继续服务
```

**方案 2：主备切换**

```java
@Component
public class HaSnowflakeGenerator {
    
    private final SnowflakeIdGenerator primary;
    private final SnowflakeIdGenerator secondary;
    
    @Autowired(required = false)
    private HealthChecker healthChecker;
    
    public long nextId() {
        try {
            if (healthChecker != null && !healthChecker.isHealthy()) {
                // 主节点不健康，使用备用
                return secondary.nextId();
            }
            return primary.nextId();
        } catch (Exception e) {
            // 主节点失败，切换到备用
            log.warn("主生成器失败，切换到备用", e);
            return secondary.nextId();
        }
    }
}
```

## 7. 最佳实践

### ✅ DO（应该做的）

1. **合理配置机器 ID**
   - 小集群：配置文件或启动参数
   - 大集群：ZooKeeper 自动分配

2. **处理时钟回拨**
   - 小幅度回拨：等待
   - 大幅度回拨：告警 + 人工介入

3. **前端使用字符串接收**
   - 避免 JavaScript 精度丢失
   - 使用 `@JsonSerialize(using = ToStringSerializer.class)`

4. **监控 ID 生成情况**
   - 记录 ID 生成速率
   - 监控时钟回拨事件
   - 告警异常情况

5. **定期备份和测试**
   - 测试时钟回拨场景
   - 测试节点故障切换
   - 验证 ID 唯一性

---

### ❌ DON'T（不应该做的）

1. **不要硬编码机器 ID**
   ```java
   // ❌ 错误
   new SnowflakeIdGenerator(1, 0);
   
   // ✅ 正确：从配置读取
   new SnowflakeIdGenerator(workerId, datacenterId);
   ```

2. **不要忽略时钟回拨**
   ```java
   // ❌ 错误：直接忽略
   if (timestamp < lastTimestamp) {
       // 什么都不做
   }
   
   // ✅ 正确：处理回拨
   if (timestamp < lastTimestamp) {
       handleClockBackwards(timestamp);
   }
   ```

3. **不要在分布式环境中使用相同的机器 ID**
   ```
   节点 1: workerId=1
   节点 2: workerId=1  ← ❌ 会生成重复 ID！
   ```

4. **不要频繁创建生成器实例**
   ```java
   // ❌ 错误：每次调用都创建新实例
   public long generateId() {
       return new SnowflakeIdGenerator(1, 0).nextId();
   }
   
   // ✅ 正确：单例模式
   @Component
   public class IdGeneratorService {
       private final SnowflakeIdGenerator generator = new SnowflakeIdGenerator(1, 0);
       
       public long generateId() {
           return generator.nextId();
       }
   }
   ```
