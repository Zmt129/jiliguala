## 1. 核心概念：什么是 RBAC？

### 🤔 通俗解释：公司门禁卡模型

想象你在一家大公司上班：
*   **用户 (User)** 就是你本人。
*   **角色 (Role)** 是你的职位（如：经理、财务、保安）。
*   **权限 (Permission)** 是你手里钥匙能打开的门（如：财务室、机房、食堂）。

**为什么要加一层“角色”？**
如果公司有 1000 个员工，每个人能进的门都不一样。如果没有角色，管理员要给 1000 个人分别配钥匙，累死也配不完。
有了角色，管理员只需要给“经理”这个职位配好钥匙。新员工入职时，只要告诉他：“你是经理”，他自然就拥有了经理的所有权限。

### 🏗️ RBAC 的演进
*   **RBAC0 (基础模型)：** 用户-角色-权限。
*   **RBAC1 (层级模型)：** 角色可以继承。比如“高级经理”自动拥有“普通经理”的所有权限。
*   **RBAC2 (约束模型)：** 互斥角色。比如“会计”和“出纳”不能是同一个人（职责分离）。
*   **RBAC3 (统一模型)：** 包含以上所有特性。

## 2. 数据库模型设计

这是 RBAC 系统的基石，通常由 5 张表组成：

### 📊 ER 图逻辑
1.  `sys_user`: 用户表
2.  `sys_role`: 角色表
3.  `sys_menu` (或 `sys_permission`): 权限/菜单表
4.  `sys_user_role`: 用户-角色关联表
5.  `sys_role_menu`: 角色-权限关联表

### 💻 SQL 示例 (MySQL) - 增强版

```sql
-- 1. 用户表
CREATE TABLE sys_user (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL UNIQUE COMMENT '用户名',
    password VARCHAR(100) NOT NULL COMMENT 'BCrypt加密密码',
    salt VARCHAR(50) COMMENT '盐值(BCrypt已内置可省略)',
    status TINYINT DEFAULT 1 COMMENT '状态：1正常 0禁用',
    dept_id BIGINT COMMENT '所属部门ID(用于数据权限)',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 2. 角色表
CREATE TABLE sys_role (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    role_name VARCHAR(50) NOT NULL COMMENT '角色名称',
    role_code VARCHAR(50) NOT NULL UNIQUE COMMENT '角色编码(如: ADMIN, EDITOR)',
    data_scope TINYINT DEFAULT 1 COMMENT '数据范围：1全部 2本部门 3仅本人'
);

-- 3. 权限/菜单表
CREATE TABLE sys_menu (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    parent_id BIGINT DEFAULT 0 COMMENT '父菜单ID',
    menu_name VARCHAR(50) NOT NULL COMMENT '菜单名称',
    perms VARCHAR(100) COMMENT '权限标识(如: user:add)',
    type TINYINT COMMENT '类型：1目录 2菜单 3按钮',
    path VARCHAR(200) COMMENT '前端路由路径',
    component VARCHAR(200) COMMENT '前端组件路径',
    icon VARCHAR(50) COMMENT '菜单图标',
    sort_order INT DEFAULT 0 COMMENT '显示排序'
);

-- 4. 用户-角色关联表
CREATE TABLE sys_user_role (
    user_id BIGINT NOT NULL,
    role_id BIGINT NOT NULL,
    PRIMARY KEY (user_id, role_id)
);

-- 5. 角色-权限关联表
CREATE TABLE sys_role_menu (
    role_id BIGINT NOT NULL,
    menu_id BIGINT NOT NULL,
    PRIMARY KEY (role_id, menu_id)
);
```

### 💡 设计细节说明
*   **perms 字段：** 这是后端校验的核心。例如 `system:user:export` 代表系统模块下用户管理的导出按钮。
*   **type 字段：** 区分是左侧菜单栏（Menu）还是页面上的按钮（Button）。只有 Menu 类型才需要配置前端路由。
*   **data_scope：** 这是一个高级字段，用于实现“数据权限”，决定用户能看到多少行数据。

## 3. 后端实现方案 (Spring Security + JWT)

### 🔐 完整的认证授权流程图

```
1. 登录请求 
   ↓
2. 验证账号密码 (BCrypt) 
   ↓
3. 查询用户拥有的所有角色和权限标识 (List<String>)
   ↓
4. 生成 JWT Token (将 UserID 放入 Payload)
   ↓
5. 将权限列表存入 Redis (Key: "auth:" + UserID, Value: List<String>, TTL: 2h)
   ↓
6. 返回 Token 给前端
```

### 🛡️ 过滤器链工作原理
当用户携带 Token 访问接口时：
1.  **JwtAuthenticationFilter:** 拦截请求，解析 Token 得到 UserID。
2.  **Redis 查询:** 根据 UserID 从 Redis 取出权限列表。
3.  **构建上下文:** 将权限封装成 `UsernamePasswordAuthenticationToken` 存入 `SecurityContextHolder`。
4.  **业务处理:** Controller 接收到请求。
5.  **注解校验:** `@PreAuthorize` 检查当前上下文是否包含所需权限。

### 💻 代码实战：如何优雅地获取权限？

#### 1. 自定义 UserDetailsService
```java
@Service
public class UserDetailsServiceImpl implements UserDetailsService {
    @Autowired private UserService userService;

    @Override
    public UserDetails loadUserByUsername(String username) {
        User user = userService.getByUsername(username);
        if (user == null) throw new UsernameNotFoundException("用户不存在");
        
        // 关键：这里只查权限标识，不查菜单结构
        List<String> perms = userService.getUserPerms(user.getId());
        
        return new org.springframework.security.core.userdetails.User(
            user.getUsername(),
            user.getPassword(),
            AuthorityUtils.createAuthorityList(perms.toArray(new String[0]))
        );
    }
}
```

#### 2. 权限校验注解的细节
*   `hasAuthority('user:add')`: 必须拥有该具体权限。
*   `hasRole('ADMIN')`: 必须拥有该角色（Spring Security 会自动加 `ROLE_` 前缀）。
*   `hasAnyAuthority('user:add', 'user:edit')`: 拥有其中一个即可。

## 4. 前端权限控制

前端权限控制的目的是：**不该看的不显示，不该点的不能点。**

### 🎨 页面级权限（动态路由）
根据用户角色，动态生成左侧菜单栏。
*   **实现：** 登录后获取菜单树，利用 Vue Router 的 `addRoute` 动态挂载路由。

### 🔘 按钮级权限（指令控制）
封装一个自定义指令 `v-auth`。

```javascript
// Vue 自定义指令示例
app.directive('auth', {
  mounted(el, binding) {
    const perms = store.getters.perms; // 从 Store 获取权限列表
    if (!perms.includes(binding.value)) {
      el.parentNode.removeChild(el); // 如果没有权限，直接移除 DOM
    }
  }
});
```

**使用：**
```html
<!-- 只有拥有 user:add 权限才显示该按钮 -->
<button v-auth="'user:add'">新增用户</button>
```

## 5. 高级特性：数据权限与动态路由

### 📊 数据权限 (Data Scope) - 也就是“你能看谁的数据”

**场景：** 同样是“查看订单”权限，销售经理能看到全公司的订单，而普通销售只能看到自己创建的订单。

**实现方案：AOP + MyBatis 拦截器**
1.  **定义注解：** `@DataScope(deptAlias = "d", userAlias = "u")`
2.  **AOP 拦截：** 在 Service 方法执行前，获取当前用户的 `data_scope`。
3.  **拼接 SQL：**
    *   如果是“本部门”：自动在 SQL 后面加上 `AND d.dept_id IN (101, 102)`
    *   如果是“仅本人”：自动加上 `AND u.create_by = 'zhangsan'`

### 🔄 动态路由 - 也就是“左边菜单栏怎么变”

**后端返回结构：**
```json
[
  {
    "name": "System",
    "path": "/system",
    "component": "Layout",
    "children": [
      {
        "name": "User",
        "path": "user",
        "component": "system/user/index",
        "meta": { "title": "用户管理", "icon": "user" }
      }
    ]
  }
]
```
**前端处理：** 拿到这个 JSON 后，遍历并使用 `router.addRoute()` 动态注册到 Vue Router 中。

## 6. 最佳实践与避坑指南

### ✅ DO (建议这样做)
1.  **权限标识命名规范：** 采用 `模块:子模块:操作`，例如 `sys:user:export`。这样在数据库中排序整齐，也好管理。
2.  **超级管理员特权：** 在代码里写死一个判断：如果角色编码是 `admin`，则跳过所有权限校验，直接放行。
3.  **缓存更新策略：** 当管理员修改了某个角色的权限后，必须**清除该角色下所有在线用户的 Redis 权限缓存**，否则用户要退出重登才能生效。
4.  **按钮级权限也要有：** 即使是页面里的“删除”按钮，也要对应一个 `perms` 标识，防止有人直接调 API。

### ❌ DON'T (千万别这样做)
1.  **不要在前端存权限逻辑：** 前端 `v-if` 隐藏按钮只是“掩耳盗铃”，后端接口必须再次校验 `@PreAuthorize`。
2.  **不要在 Token 里塞太多东西：** JWT 是有长度限制的。如果权限很多，Token 会变大，导致 HTTP Header 溢出。**正确做法：Token 只存 UserID，权限详情查 Redis。**
3.  **不要忽略“禁用”状态：** 用户被禁用后，不仅要拦截登录，还要踢掉该用户已经登录的 Token（可以通过 Redis 黑名单实现）。

### 💡 常见问题解答 (FAQ)
*   **Q: 用户改了密码，旧 Token 还能用吗？**
    *   A: 能用。因为 JWT 是无状态的。如果想立即失效，需要将旧 Token 加入 Redis 黑名单。
*   **Q: 如何实现“互斥角色”？（如既是会计又是出纳）**
    *   A: 在分配角色时增加校验逻辑，如果检测到冲突的角色组合，禁止分配。

### 💻 关键代码片段

#### 1. Mapper 层：多表联查权限
在 [SysUserMapper.java](file:///D:/git/jiliguala/buding/src/main/java/com/example/auth/mapper/SysUserMapper.java) 中，我们通过联查 5 张表直接获取用户的权限标识列表：

```java
@Select("SELECT DISTINCT m.perms FROM sys_menu m " +
        "JOIN sys_role_menu rm ON m.id = rm.menu_id " +
        "JOIN sys_user_role ur ON rm.role_id = ur.role_id " +
        "WHERE ur.user_id = #{userId} AND m.perms IS NOT NULL")
List<String> selectPermsByUserId(Long userId);
```

#### 2. Service 层：登录与 Token 生成
在 [AuthServiceImpl.java](file:///D:/git/jiliguala/buding/src/main/java/com/example/auth/service/impl/AuthServiceImpl.java) 中，处理登录校验并返回 JWT：

```java
public String login(String username, String password) {
    SysUser user = userMapper.selectOne(...);
    if (user == null || !passwordEncoder.matches(password, user.getPassword())) {
        throw new RuntimeException("用户名或密码错误");
    }
    return jwtUtil.generateToken(user.getId(), user.getUsername());
}
```

#### 3. Controller 层：统一响应
在 [AuthController.java](file:///D:/git/jiliguala/buding/src/main/java/com/example/auth/controller/AuthController.java) 中，提供标准的 RESTful 接口：

*   `POST /api/auth/login`: 登录获取 Token。
*   `GET /api/auth/info`: 获取当前用户详情、权限列表及动态菜单树。
