## 1. 分布式锁

### 🔍 为什么需要分布式锁？

在单机环境下，`synchronized` 或 `ReentrantLock` 可以解决并发问题。但在分布式集群中，不同 JVM 进程间的线程无法通过本地锁互斥，必须借助第三方组件实现全局互斥。

### 🛠️ 常见实现方案对比

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| **数据库唯一索引** | 简单可靠 | 性能差，无超时机制 | ⭐⭐ |
| **ZooKeeper** | 强一致性，支持 Watch | 性能一般，维护成本高 | ⭐⭐⭐ |
| **Redis (SETNX)** | 性能极高，简单易用 | 极端情况可能失效 | ⭐⭐⭐⭐⭐ |
| **Redisson** | 封装完善，支持看门狗 | 依赖 Redis | ⭐⭐⭐⭐⭐ |

---

### 🚀 Redis 实现分布式锁（Redisson）

#### 核心原理
1. **加锁：** 使用 `SET key value NX PX milliseconds` 保证原子性。
2. **续期（看门狗）：** 如果业务没执行完，后台线程自动延长锁的过期时间。
3. **解锁：** 使用 Lua 脚本保证“判断 + 删除”的原子性。

#### 代码示例
```java
@Autowired
private RedissonClient redissonClient;

public void doBusiness() {
    RLock lock = redissonClient.getLock("myLock");
    try {
        // 尝试加锁，最多等待 10 秒，上锁后 30 秒自动释放
        boolean isLocked = lock.tryLock(10, 30, TimeUnit.SECONDS);
        if (isLocked) {
            // 执行业务逻辑
        }
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    } finally {
        // 只有持有锁的线程才能解锁
        if (lock.isHeldByCurrentThread()) {
            lock.unlock();
        }
    }
}
```

#### 常见问题：Redlock 算法
当 Redis 是主从架构时，如果 Master 挂掉且锁还没同步到 Slave，可能导致锁失效。Redlock 算法通过向多个独立的 Redis 实例申请锁来解决此问题。

## 2. 分布式事务理论

### 🎯 CAP 定理
- **C (Consistency)：** 一致性。
- **A (Availability)：** 可用性。
- **P (Partition Tolerance)：** 分区容错性。
**结论：** 分布式系统只能满足其中两项，通常选择 AP 或 CP。

### 🎯 BASE 理论
- **BA (Basically Available)：** 基本可用。
- **S (Soft State)：** 软状态（允许中间状态）。
- **E (Eventually Consistent)：** 最终一致性。

## 3. 分布式事务解决方案

| 方案 | 原理 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|---------|
| **2PC (XA)** | 两阶段提交，强一致 | 实现简单，强一致 | 性能差，阻塞资源 | 银行核心系统 |
| **TCC** | Try-Confirm-Cancel | 性能好，可控 | 代码侵入性强 | 金融支付 |
| **本地消息表** | 消息与业务同库 | 最终一致，可靠 | 耦合业务代码 | 传统单体改造 |
| **MQ 事务消息** | 利用 MQ 半消息机制 | 解耦，最终一致 | 依赖 MQ 特性 | 电商订单 |
| **Seata (AT)** | 代理数据源，自动回滚 | 无侵入，易用 | 依赖全局锁 | 大多数微服务 |

## 4. Seata 实战

### 🏗️ Seata 三大组件
- **TC (Transaction Coordinator)：** 事务协调器，维护全局事务状态。
- **TM (Transaction Manager)：** 事务管理器，开启/提交/回滚全局事务。
- **RM (Resource Manager)：** 资源管理器，管理分支事务。

### 📝 AT 模式流程
1. **一阶段：** RM 解析 SQL，生成 undo_log，执行并提交本地事务。
2. **二阶段：** 
   - 成功：TC 通知 RM 异步删除 undo_log。
   - 失败：TC 通知 RM 根据 undo_log 回滚数据。

### 💻 代码集成
```java
// 1. 引入依赖
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-seata</artifactId>
</dependency>

// 2. 开启全局事务
@GlobalTransactional
public void createOrder(Order order) {
    // 调用库存服务
    storageService.deduct(order.getProductId(), order.getCount());
    // 调用账户服务
    accountService.debit(order.getUserId(), order.getAmount());
    // 创建订单
    orderRepository.save(order);
}
```
