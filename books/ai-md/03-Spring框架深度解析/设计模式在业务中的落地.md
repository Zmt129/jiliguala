## 1. 为什么需要设计模式？

在实际开发中，我们常遇到以下痛点：
*   **代码臃肿：** 一个方法里塞满了 `if-else` 或 `switch-case`。
*   **牵一发而动全身：** 修改一个小功能，导致整个类都要重新测试。
*   **扩展困难：** 增加一个新业务类型，需要修改多处核心代码。

**设计模式的核心价值：** 将**变化**与**稳定**分离，遵循 **开闭原则 (OCP)**——对扩展开放，对修改关闭。

## 2. 策略模式：消除复杂的 if-else

### 🔍 场景
根据不同的支付方式（微信、支付宝、银行卡）执行不同的扣款逻辑。

### ❌ 传统写法
```java
public void pay(String type, BigDecimal amount) {
    if ("WECHAT".equals(type)) {
        // 微信支付逻辑...
    } else if ("ALIPAY".equals(type)) {
        // 支付宝支付逻辑...
    } else if ("BANK".equals(type)) {
        // 银行卡支付逻辑...
    }
}
```

### ✅ 策略模式重构
1.  **定义接口：**
    ```java
    public interface PaymentStrategy {
        void pay(BigDecimal amount);
    }
    ```
2.  **实现具体策略：**
    ```java
    @Component("wechatPay")
    public class WechatPayStrategy implements PaymentStrategy {
        public void pay(BigDecimal amount) { /* ... */ }
    }
    
    @Component("alipayPay")
    public class AlipayPayStrategy implements PaymentStrategy {
        public void pay(BigDecimal amount) { /* ... */ }
    }
    ```
3.  **使用 Map 注入（Spring 技巧）：**
    ```java
    @Service
    public class PaymentService {
        @Autowired
        private Map<String, PaymentStrategy> strategyMap;

        public void executePay(String type, BigDecimal amount) {
            PaymentStrategy strategy = strategyMap.get(type.toLowerCase() + "Pay");
            if (strategy == null) throw new BusinessException("不支持的支付方式");
            strategy.pay(amount);
        }
    }
    ```

## 3. 模板方法模式：统一业务流程骨架

### 🔍 场景
处理不同类型的订单导出（Excel, CSV, PDF），流程都是：查询数据 -> 格式化 -> 写入文件 -> 上传 OSS。

### ✅ 模板方法实现
```java
public abstract class OrderExportTemplate {
    
    // 1. 最终方法，定义流程骨架
    public final void exportOrder(Long orderId) {
        List<Order> data = queryData(orderId); // 通用
        byte[] fileContent = formatData(data); // 抽象方法，由子类实现
        String url = uploadToOss(fileContent); // 通用
        saveLog(url); // 通用
    }

    protected abstract byte[] formatData(List<Order> data);
    
    // ... 其他通用方法
}

// 子类只需关注差异化部分
@Component
public class ExcelExportHandler extends OrderExportTemplate {
    @Override
    protected byte[] formatData(List<Order> data) {
        return EasyExcelUtils.writeToBytes(data);
    }
}
```

## 4. 责任链模式：解耦复杂的校验逻辑

### 🔍 场景
用户下单前需要经过：库存校验 -> 优惠券校验 -> 风控校验 -> 余额校验。

### ✅ 责任链实现
1.  **定义处理器：**
    ```java
    public abstract class OrderValidator {
        protected OrderValidator next;
        
        public void setNext(OrderValidator next) {
            this.next = next;
        }

        public final void validate(Order order) {
            doValidate(order);
            if (next != null) next.validate(order);
        }

        protected abstract void doValidate(Order order);
    }
    ```
2.  **组装链条（Spring 中可利用 List 自动注入）：**
    ```java
    @Service
    public class OrderValidationChain {
        @Autowired
        private List<OrderValidator> validators; // Spring 按顺序注入

        public void process(Order order) {
            for (int i = 0; i < validators.size() - 1; i++) {
                validators.get(i).setNext(validators.get(i + 1));
            }
            validators.get(0).validate(order);
        }
    }
    ```

## 5. 观察者模式：实现业务解耦

### 🔍 场景
用户注册成功后，需要：发送欢迎邮件、赠送积分、记录审计日志。这些操作不应该阻塞注册主流程。

### ✅ Spring 事件驱动实现
1.  **定义事件：**
    ```java
    public class UserRegisteredEvent extends ApplicationEvent {
        private final Long userId;
        public UserRegisteredEvent(Object source, Long userId) {
            super(source);
            this.userId = userId;
        }
        public Long getUserId() { return userId; }
    }
    ```
2.  **发布事件：**
    ```java
    @Service
    public class UserService {
        @Autowired
        private ApplicationEventPublisher publisher;

        public void register(User user) {
            // 1. 保存用户
            userMapper.insert(user);
            // 2. 发布事件（异步执行后续逻辑）
            publisher.publishEvent(new UserRegisteredEvent(this, user.getId()));
        }
    }
    ```
3.  **监听事件：**
    ```java
    @Component
    public class EmailListener {
        @EventListener
        @Async // 开启异步，不阻塞主线程
        public void handleUserRegistered(UserRegisteredEvent event) {
            emailService.sendWelcomeEmail(event.getUserId());
        }
    }
    ```

## 6. 工厂模式：简化对象创建

### 🔍 场景
根据配置动态创建不同的通知渠道（短信、邮件、站内信）。

### ✅ 简单工厂实现
```java
@Component
public class NotificationFactory {
    
    @Autowired
    private SmsNotification smsNotification;
    @Autowired
    private EmailNotification emailNotification;

    public NotificationService getNotification(String type) {
        if ("SMS".equalsIgnoreCase(type)) return smsNotification;
        if ("EMAIL".equalsIgnoreCase(type)) return emailNotification;
        throw new IllegalArgumentException("无效的通知类型");
    }
}
```

## ⚠️ 避坑指南

1.  **不要过度设计：** 如果只有两个分支，`if-else` 比策略模式更直观。
2.  **命名即文档：** 策略类和处理器类的命名要清晰表达其业务含义。
3.  **结合 Spring 特性：** 善用 `@Autowired Map/List` 和 `ApplicationEventPublisher`，能让模式落地更优雅。
4.  **保持单一职责：** 每个策略或处理器只负责一件事，不要把多个逻辑揉在一起。

---

**记住：设计模式是解决问题的工具，而不是炫技的手段。当代码开始“腐烂”时，才是引入模式的最佳时机！** 🚀
