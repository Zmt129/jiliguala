## 1. 缓存三大问题

### 🤔 通俗解释

**想象一个图书馆：**

```
正常情况：
读者 → 查目录（缓存）→ 找到书的位置 → 借书
90% 的请求都能在目录中找到，快速响应


问题 1：缓存穿透（查不存在的数据）
读者 → 查目录 → 没有 → 去书架找 → 也没有
恶意用户疯狂查询不存在的书号
结果：每次都查书架，书架被挤爆！


问题 2：缓存雪崩（大量缓存同时过期）
图书馆目录系统突然崩溃（或所有目录卡同时失效）
所有读者都直接冲向书架
结果：书架被挤爆，图书馆瘫痪！


问题 3：缓存击穿（热点数据过期）
某本热门书的目录卡突然消失
成千上万的读者同时去书架找这本书
结果：书架前排队，其他读者也受影响！
```

---

### 📊 问题对比

| 问题 | 原因 | 影响 | 关键特征 |
|------|------|------|---------|
| **穿透** | 查询不存在的数据 | 请求直达数据库 | 数据本身不存在 |
| **雪崩** | 大量缓存同时过期 | 数据库压力剧增 | 大面积缓存失效 |
| **击穿** | 热点数据过期 | 单个 key 压力巨大 | 单个 key 高并发 |

## 2. 缓存穿透

### 🔍 什么是缓存穿透？

**定义：** 查询一个**根本不存在的数据**，缓存层和存储层都不会命中，导致每次请求都打到数据库。

**场景：**
```
用户 ID: -1, 0, 999999999（不存在的 ID）
商品编号: "ABC123"（不存在的商品）

攻击者故意构造大量不存在的 key 进行查询
```

**危害：**
- ❌ 数据库压力剧增
- ❌ 可能导致数据库宕机
- ❌ 系统整体响应变慢

---

### 🛡️ 解决方案

#### 方案 1：缓存空对象（推荐）

**思路：** 即使数据不存在，也在缓存中存储一个空值，避免重复查询数据库。

```java
@Service
public class ProductService {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    @Autowired
    private ProductRepository productRepository;
    
    /**
     * 查询商品（解决缓存穿透）
     */
    public Product getProduct(String productId) {
        
        // 1. 从缓存中获取
        String cached = redisTemplate.opsForValue().get("product:" + productId);
        
        // 2. 缓存命中
        if (cached != null) {
            // 判断是否是空对象标记
            if ("NULL_OBJECT".equals(cached)) {
                return null;  // 数据确实不存在
            }
            return JSON.parseObject(cached, Product.class);
        }
        
        // 3. 缓存未命中，查询数据库
        Product product = productRepository.findById(productId).orElse(null);
        
        // 4. 将结果写入缓存
        if (product != null) {
            // 存在：缓存真实数据，设置正常过期时间
            redisTemplate.opsForValue().set(
                "product:" + productId,
                JSON.toJSONString(product),
                3600, TimeUnit.SECONDS  // 1 小时
            );
        } else {
            // 不存在：缓存空对象，设置较短过期时间
            redisTemplate.opsForValue().set(
                "product:" + productId,
                "NULL_OBJECT",
                300, TimeUnit.SECONDS  // 5 分钟
            );
        }
        
        return product;
    }
}
```

**优点：**
- ✅ 实现简单
- ✅ 有效防止穿透

**缺点：**
- ❌ 占用额外内存（存储大量空对象）
- ❌ 可能存在短暂不一致（数据库已插入，缓存还是空对象）

**优化：** 使用更短的过期时间，定期清理空对象。

#### 方案 2：布隆过滤器（Bloom Filter）

**思路：** 在缓存之前加一层布隆过滤器，快速判断数据是否存在。

**原理：**
```
布隆过滤器是一个位数组 + 多个哈希函数

添加数据：
1. 通过 k 个哈希函数计算 k 个位置
2. 将这 k 个位置设置为 1

查询数据：
1. 通过 k 个哈希函数计算 k 个位置
2. 如果所有位置都是 1 → 可能存在
3. 如果有任何一个位置是 0 → 一定不存在
```

**特点：**
- ✅ 空间效率极高
- ✅ 查询速度快
- ❌ 有误判率（可能把不存在的判断为存在）
- ❌ 不支持删除

**实现：**

```java
@Component
public class BloomFilterService {
    
    private BloomFilter<String> bloomFilter;
    
    @PostConstruct
    public void init() {
        // 创建布隆过滤器
        // 预期元素数量：100 万
        // 误判率：0.01%
        bloomFilter = BloomFilter.create(
            Funnels.stringFunnel(Charset.forName("UTF-8")),
            1_000_000,
            0.0001
        );
        
        // 初始化：将所有存在的商品 ID 加入布隆过滤器
        List<String> productIds = productRepository.findAllIds();
        for (String id : productIds) {
            bloomFilter.put(id);
        }
    }
    
    /**
     * 判断商品 ID 是否可能存在
     */
    public boolean mightExist(String productId) {
        return bloomFilter.mightContain(productId);
    }
    
    /**
     * 添加商品 ID
     */
    public void addProductId(String productId) {
        bloomFilter.put(productId);
    }
}

// 使用
@Service
public class ProductService {
    
    @Autowired
    private BloomFilterService bloomFilterService;
    
    public Product getProduct(String productId) {
        
        // 1. 布隆过滤器判断
        if (!bloomFilterService.mightExist(productId)) {
            // 一定不存在，直接返回
            return null;
        }
        
        // 2. 可能存在，继续查缓存和数据库
        // ...（同方案 1）
    }
}
```

**依赖：**
```xml
<dependency>
    <groupId>com.google.guava</groupId>
    <artifactId>guava</artifactId>
    <version>32.1.3-jre</version>
</dependency>
```

**优点：**
- ✅ 内存占用极小
- ✅ 性能极高
- ✅ 适合大数据量场景

**缺点：**
- ❌ 有误判率
- ❌ 不支持删除（需要重建）
- ❌ 实现复杂

#### 方案 3：参数校验

**思路：** 在接口层进行严格的参数校验，拦截非法请求。

```java
@RestController
@RequestMapping("/api/products")
public class ProductController {
    
    @GetMapping("/{id}")
    public ApiResponse<Product> getProduct(
            @PathVariable @Min(1) Long id) {  // 校验 ID >= 1

        Product product = productService.getProduct(id);
        return ApiResponse.success(product);
    }
    
    @GetMapping
    public ApiResponse<List<Product>> listProducts(
            @RequestParam @Min(1) Integer page,
            @RequestParam @Min(1) @Max(100) Integer size) {
        
        // 业务逻辑
        return ApiResponse.success(productService.list(page, size));
    }
}
```

**优点：**
- ✅ 简单有效
- ✅ 拦截明显非法请求

**缺点：**
- ❌ 无法阻止精心构造的合法但不存在的 ID

---

### 💡 最佳实践

**组合方案：**
1. **第一层：** 参数校验（拦截明显非法请求）
2. **第二层：** 布隆过滤器（快速判断是否存在）
3. **第三层：** 缓存空对象（防止重复查询数据库）

```
请求 → 参数校验 → 布隆过滤器 → 缓存 → 数据库
         ↓            ↓           ↓       ↓
       拦截非法    一定不存在   命中返回  查询并缓存
                   直接返回     空对象
```

## 3. 缓存雪崩

### 🔍 什么是缓存雪崩？

**定义：** 大量缓存在**同一时间过期**，或者**缓存服务器宕机**，导致所有请求都打到数据库，造成数据库压力剧增甚至宕机。

**场景：**
```
场景 1：集中过期
- 10 万个 key 都在凌晨 2:00 过期
- 2:00 一到，所有请求都查数据库

场景 2：缓存宕机
- Redis 集群全部挂掉
- 所有请求直接打到数据库
```

**危害：**
- ❌ 数据库瞬间压力巨大
- ❌ 可能导致数据库宕机
- ❌ 整个系统不可用

---

### 🛡️ 解决方案

#### 方案 1：随机过期时间（推荐）

**思路：** 给缓存的过期时间增加一个随机值，避免同时过期。

```java
@Service
public class ProductService {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    public void cacheProduct(Product product) {
        
        // ❌ 错误：固定过期时间，容易雪崩
        // redisTemplate.opsForValue().set(
        //     "product:" + product.getId(),
        //     JSON.toJSONString(product),
        //     3600, TimeUnit.SECONDS  // 所有缓存都是 1 小时
        // );
        
        // ✅ 正确：随机过期时间
        int baseExpire = 3600;  // 基础过期时间 1 小时
        int randomExpire = new Random().nextInt(1800);  // 随机 0-30 分钟
        int expire = baseExpire + randomExpire;  // 实际过期时间：1-1.5 小时
        
        redisTemplate.opsForValue().set(
            "product:" + product.getId(),
            JSON.toJSONString(product),
            expire, TimeUnit.SECONDS
        );
    }
}
```

**效果：**
```
原来：所有缓存都在 12:00:00 过期
现在：缓存在 12:00:00 ~ 12:30:00 之间陆续过期
```

---

#### 方案 2：缓存永不过期（物理不过期，逻辑过期）

**思路：** 缓存不设置过期时间，而是在 value 中包含逻辑过期时间，由后台线程异步更新。

```java
@Data
public class CacheObject<T> {
    private T data;
    private LocalDateTime expireTime;  // 逻辑过期时间
}

@Service
public class ProductService {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    @Autowired
    private ThreadPoolTaskExecutor executor;
    
    /**
     * 获取商品（逻辑过期）
     */
    public Product getProduct(String productId) {
        
        String key = "product:" + productId;
        String cached = redisTemplate.opsForValue().get(key);
        
        if (cached == null) {
            // 缓存不存在，查询数据库并设置缓存
            return loadAndCache(productId);
        }
        
        CacheObject<Product> cacheObj = JSON.parseObject(cached, 
            new TypeReference<CacheObject<Product>>() {});
        
        // 检查逻辑过期时间
        if (cacheObj.getExpireTime().isBefore(LocalDateTime.now())) {
            // 已过期，异步更新缓存
            executor.submit(() -> {
                loadAndCache(productId);
            });
            
            // 返回旧数据（保证可用性）
            return cacheObj.getData();
        }
        
        // 未过期，返回缓存数据
        return cacheObj.getData();
    }
    
    /**
     * 加载数据并缓存
     */
    private Product loadAndCache(String productId) {
        Product product = productRepository.findById(productId).orElse(null);
        
        if (product != null) {
            CacheObject<Product> cacheObj = new CacheObject<>();
            cacheObj.setData(product);
            cacheObj.setExpireTime(LocalDateTime.now().plusHours(1));  // 1 小时后逻辑过期
            
            redisTemplate.opsForValue().set(
                "product:" + productId,
                JSON.toJSONString(cacheObj)
                // 注意：不设置 TTL，物理上永不过期
            );
        }
        
        return product;
    }
}
```

**优点：**
- ✅ 不会出现集中过期
- ✅ 性能稳定

**缺点：**
- ❌ 实现复杂
- ❌ 可能返回过期数据
- ❌ 需要额外的存储空间

#### 方案 3：多级缓存

**思路：** 本地缓存 + 分布式缓存，分散压力。

```java
@Service
public class ProductService {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    // 本地缓存（Caffeine）
    private final Cache<String, Product> localCache = Caffeine.newBuilder()
        .maximumSize(1000)
        .expireAfterWrite(10, TimeUnit.MINUTES)
        .build();
    
    public Product getProduct(String productId) {
        
        // 1. 先查本地缓存
        Product product = localCache.getIfPresent(productId);
        if (product != null) {
            return product;
        }
        
        // 2. 再查分布式缓存
        String cached = redisTemplate.opsForValue().get("product:" + productId);
        if (cached != null) {
            product = JSON.parseObject(cached, Product.class);
            localCache.put(productId, product);  // 写入本地缓存
            return product;
        }
        
        // 3. 最后查数据库
        product = productRepository.findById(productId).orElse(null);
        if (product != null) {
            redisTemplate.opsForValue().set(
                "product:" + productId,
                JSON.toJSONString(product),
                3600 + new Random().nextInt(1800), TimeUnit.SECONDS
            );
            localCache.put(productId, product);
        }
        
        return product;
    }
}
```

**优点：**
- ✅ 分散压力
- ✅ 提高命中率
- ✅ 降低网络开销

**缺点：**
- ❌ 数据一致性问题
- ❌ 实现复杂

#### 方案 4：限流与降级

**思路：** 当检测到异常时，限制流量或返回降级数据。

```java
@Service
public class ProductService {
    
    @Autowired
    private RedisTemplate<String, String> redisTemplate;
    
    /**
     * 带限流的商品查询
     */
    public Product getProduct(String productId) {
        
        // 限流检查
        if (!tryAcquire(productId)) {
            // 触发限流，返回降级数据
            return getFallbackProduct(productId);
        }
        
        try {
            // 正常查询逻辑
            return queryProduct(productId);
        } catch (Exception e) {
            // 异常时返回降级数据
            log.error("查询商品失败", e);
            return getFallbackProduct(productId);
        }
    }
    
    /**
     * 尝试获取令牌（限流）
     */
    private boolean tryAcquire(String productId) {
        String key = "rate_limit:" + productId;
        Long count = redisTemplate.opsForValue().increment(key);
        
        if (count == 1) {
            // 第一次访问，设置过期时间
            redisTemplate.expire(key, 1, TimeUnit.SECONDS);
        }
        
        // 每秒最多 100 次请求
        return count <= 100;
    }
    
    /**
     * 降级数据
     */
    private Product getFallbackProduct(String productId) {
        // 返回默认值或空值
        Product product = new Product();
        product.setId(Long.parseLong(productId));
        product.setName("商品加载中...");
        return product;
    }
}
```

### 💡 最佳实践

**组合方案：**
1. **预防：** 随机过期时间
2. **保护：** 多级缓存
3. **兜底：** 限流 + 降级

## 4. 缓存击穿

### 🔍 什么是缓存击穿？

**定义：** 某个**热点数据**在过期的瞬间，有大量并发请求同时访问，导致这些请求都打到数据库。

**场景：**
```
热点数据：首页轮播图、秒杀商品、热点新闻

时间点：12:00:00 缓存过期
12:00:00.001 → 1000 个请求发现缓存过期
12:00:00.002 → 1000 个请求同时查数据库
```

**与雪崩的区别：**
- **雪崩：** 大量 key 同时过期
- **击穿：** 单个 key 被高并发访问

---

### 🛡️ 解决方案

#### 方案 1：互斥锁（Mutex Lock）

**思路：** 只让一个请求去查数据库，其他请求等待。

```java
@Service
public class ProductService {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    /**
     * 查询商品（解决缓存击穿）
     */
    public Product getProduct(String productId) throws InterruptedException {
        
        String key = "product:" + productId;
        String lockKey = "lock:product:" + productId;
        
        // 1. 从缓存中获取
        String cached = redisTemplate.opsForValue().get(key);
        if (cached != null) {
            return JSON.parseObject(cached, Product.class);
        }
        
        // 2. 缓存未命中，尝试获取分布式锁
        Boolean locked = redisTemplate.opsForValue().setIfAbsent(
            lockKey, "1", 10, TimeUnit.SECONDS
        );
        
        if (Boolean.TRUE.equals(locked)) {
            try {
                // 3. 获取到锁，查询数据库
                // 双重检查：可能其他线程已经更新了缓存
                cached = redisTemplate.opsForValue().get(key);
                if (cached != null) {
                    return JSON.parseObject(cached, Product.class);
                }
                
                // 4. 查询数据库
                Product product = productRepository.findById(productId).orElse(null);
                
                // 5. 写入缓存
                if (product != null) {
                    redisTemplate.opsForValue().set(
                        key,
                        JSON.toJSONString(product),
                        3600 + new Random().nextInt(1800), TimeUnit.SECONDS
                    );
                }
                
                return product;
                
            } finally {
                // 6. 释放锁
                redisTemplate.delete(lockKey);
            }
        } else {
            // 7. 未获取到锁，等待后重试
            Thread.sleep(50);
            return getProduct(productId);  // 递归重试
        }
    }
}
```

**优点：**
- ✅ 保证只有一个请求查数据库
- ✅ 有效防止击穿

**缺点：**
- ❌ 其他请求需要等待
- ❌ 实现复杂
- ❌ 可能有死锁风险（需要设置锁超时）

---

#### 方案 2：逻辑过期（推荐）

**思路：** 不设置物理过期时间，而是通过逻辑过期时间判断，异步更新缓存。

```java
@Service
public class ProductService {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    @Autowired
    private ThreadPoolTaskExecutor executor;
    
    /**
     * 查询商品（逻辑过期，解决击穿）
     */
    public Product getProduct(String productId) {
        
        String key = "product:" + productId;
        String cached = redisTemplate.opsForValue().get(key);
        
        if (cached == null) {
            // 缓存不存在，同步加载
            return loadAndCache(productId);
        }
        
        CacheObject<Product> cacheObj = JSON.parseObject(cached, 
            new TypeReference<CacheObject<Product>>() {});
        
        // 检查逻辑过期
        if (cacheObj.getExpireTime().isBefore(LocalDateTime.now())) {
            // 已过期，异步更新（不阻塞当前请求）
            executor.submit(() -> {
                loadAndCache(productId);
            });
            
            // 返回旧数据（保证可用性）
            return cacheObj.getData();
        }
        
        // 未过期，返回缓存数据
        return cacheObj.getData();
    }
    
    private synchronized Product loadAndCache(String productId) {
        // 双重检查
        String cached = redisTemplate.opsForValue().get("product:" + productId);
        if (cached != null) {
            CacheObject<Product> cacheObj = JSON.parseObject(cached, 
                new TypeReference<CacheObject<Product>>() {});
            if (!cacheObj.getExpireTime().isBefore(LocalDateTime.now())) {
                return cacheObj.getData();
            }
        }
        
        // 查询数据库并更新缓存
        Product product = productRepository.findById(productId).orElse(null);
        if (product != null) {
            CacheObject<Product> cacheObj = new CacheObject<>();
            cacheObj.setData(product);
            cacheObj.setExpireTime(LocalDateTime.now().plusHours(1));
            
            redisTemplate.opsForValue().set(
                "product:" + productId,
                JSON.toJSONString(cacheObj)
            );
        }
        
        return product;
    }
}
```

**优点：**
- ✅ 不会阻塞请求
- ✅ 性能高
- ✅ 有效防止击穿

**缺点：**
- ❌ 可能返回过期数据
- ❌ 实现复杂

#### 方案 3：热点数据永不过期

**思路：** 对于极热点数据，不设置过期时间，通过后台任务定期更新。

```java
@Component
public class HotDataRefreshTask {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    @Autowired
    private ProductService productService;
    
    /**
     * 每小时刷新一次热点数据
     */
    @Scheduled(fixedRate = 3600000)  // 1 小时
    public void refreshHotProducts() {
        
        // 获取热点商品 ID 列表
        List<String> hotProductIds = getHotProductIds();
        
        for (String productId : hotProductIds) {
            try {
                Product product = productService.loadFromDb(productId);
                if (product != null) {
                    redisTemplate.opsForValue().set(
                        "product:" + productId,
                        JSON.toJSONString(product)
                        // 不设置过期时间
                    );
                }
            } catch (Exception e) {
                log.error("刷新热点数据失败", e);
            }
        }
    }
}
```

**优点：**
- ✅ 简单有效
- ✅ 性能最好

**缺点：**
- ❌ 只适合少量热点数据
- ❌ 数据更新有延迟

### 💡 最佳实践

**选择建议：**
- 一般场景：互斥锁
- 高性能要求：逻辑过期
- 极热点数据：永不过期 + 定时刷新

## 5. 服务熔断与降级

### 🔍 什么是熔断？

**定义：** 当某个服务出现故障或响应过慢时，暂时切断对该服务的调用，避免故障扩散。

**类比：** 电路保险丝
```
电流过大 → 保险丝熔断 → 切断电路 → 保护电器
服务异常 → 熔断器打开 → 切断调用 → 保护系统
```

---

### 🔄 熔断器状态机

```
          异常比例超过阈值
CLOSED ──────────────────→ OPEN
  ↑                          │
  │                          │ 经过休眠时间
  │                          ↓
  │                      HALF_OPEN
  │                          │
  └──────────────────────────┘
     请求成功，恢复正常
```

**三种状态：**

1. **CLOSED（关闭）**
   - 正常状态，请求正常通过
   - 监控异常情况

2. **OPEN（打开）**
   - 熔断状态，请求直接失败
   - 不调用下游服务
   - 经过一段时间后进入 HALF_OPEN

3. **HALF_OPEN（半开）**
   - 试探状态，允许少量请求通过
   - 如果成功 → CLOSED
   - 如果失败 → OPEN

---

### 🛡️ 实现方案

#### 方案 1：Sentinel（阿里开源，推荐）

**依赖：**
```xml
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-sentinel</artifactId>
</dependency>
```

**配置：**
```yaml
spring:
  cloud:
    sentinel:
      transport:
        dashboard: localhost:8080  # Sentinel 控制台
      datasource:
        ds1:
          nacos:
            server-addr: localhost:8848
            data-id: ${spring.application.name}-sentinel
            group-id: DEFAULT_GROUP
            rule-type: flow
```

**代码示例：**

```java
@Service
public class OrderService {
    
    @Autowired
    private RestTemplate restTemplate;
    
    /**
     * 调用用户服务（带熔断）
     */
    @SentinelResource(
        value = "getUser",
        blockHandler = "getUserBlockHandler",
        fallback = "getUserFallback"
    )
    public User getUser(Long userId) {
        // 调用远程服务
        return restTemplate.getForObject(
            "http://user-service/api/users/" + userId,
            User.class
        );
    }
    
    /**
     * 熔断处理（限流、降级时调用）
     */
    public User getUserBlockHandler(Long userId, BlockException ex) {
        log.warn("触发熔断：{}", ex.getMessage());
        return getDefaultUser(userId);
    }
    
    /**
     * 异常降级（业务异常时调用）
     */
    public User getUserFallback(Long userId, Throwable t) {
        log.error("调用用户服务失败", t);
        return getDefaultUser(userId);
    }
    
    private User getDefaultUser(Long userId) {
        User user = new User();
        user.setId(userId);
        user.setName("默认用户");
        return user;
    }
}
```

**Sentinel 控制台配置规则：**
- QPS 阈值：每秒最多 100 次请求
- 异常比例：超过 50% 触发熔断
- 熔断时长：30 秒

```java
@Service
public class OrderService {

    private CircuitBreakerRegistry circuitBreakerRegistry;

    private RestTemplate restTemplate;

                "http://user-service/api/users/" + userId,
                User.class
```

### 📉 服务降级

**定义：** 当系统负载过高或服务不可用时，返回简化的数据或默认值，保证核心功能可用。

**场景：**
```
正常：显示完整的商品信息（名称、价格、库存、评价、推荐）
降级：只显示商品名称和价格
```

**实现：**

```java
@Service
public class ProductService {
    
    /**
     * 获取商品详情（带降级）
     */
    @SentinelResource(value = "getProductDetail", fallback = "getProductDetailFallback")
    public ProductDetail getProductDetail(Long productId) {
        
        ProductDetail detail = new ProductDetail();
        
        // 1. 基本信息（必须）
        Product product = productRepository.findById(productId).orElseThrow();
        detail.setProduct(product);
        
        // 2. 库存信息（重要）
        detail.setStock(stockService.getStock(productId));
        
        // 3. 评价信息（可降级）
        detail.setReviews(reviewService.getReviews(productId));
        
        // 4. 推荐商品（可降级）
        detail.setRecommendations(recommendService.getRecommendations(productId));
        
        return detail;
    }
    
    /**
     * 降级方法
     */
    public ProductDetail getProductDetailFallback(Long productId, Throwable t) {
        log.warn("获取商品详情降级", t);
        
        ProductDetail detail = new ProductDetail();
        
        // 只返回基本信息
        Product product = productRepository.findById(productId).orElse(null);
        detail.setProduct(product);
        
        // 其他字段为空或默认值
        detail.setStock(0);
        detail.setReviews(Collections.emptyList());
        detail.setRecommendations(Collections.emptyList());
        
        return detail;
    }
}
```

## 7. 实战案例

### 📦 案例：电商商品查询系统

#### 需求

- QPS：10,000
- 商品数量：100 万
- 热点商品：1000 个（占 80% 流量）
- 要求：高可用、低延迟

#### 实现

```java
@Service
@Slf4j
public class ProductServiceImpl implements ProductService {
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    @Autowired
    private ProductRepository productRepository;
    
    @Autowired
    private BloomFilterService bloomFilterService;
    
    @Autowired
    private ThreadPoolTaskExecutor executor;
    
    // 本地缓存
    private final Cache<String, Product> localCache = Caffeine.newBuilder()
        .maximumSize(5000)
        .expireAfterWrite(5, TimeUnit.MINUTES)
        .build();
    
    @Override
    public Product getProduct(Long productId) {
        
        String key = "product:" + productId;
        
        // 1. 参数校验
        if (productId == null || productId <= 0) {
            throw new IllegalArgumentException("无效的商品 ID");
        }
        
        // 2. 本地缓存
        Product product = localCache.getIfPresent(key);
        if (product != null) {
            return product;
        }
        
        // 3. 布隆过滤器
        if (!bloomFilterService.mightExist(String.valueOf(productId))) {
            return null;
        }
        
        // 4. 分布式缓存
        String cached = redisTemplate.opsForValue().get(key);
        if (cached != null) {
            if ("NULL".equals(cached)) {
                return null;
            }
            product = JSON.parseObject(cached, Product.class);
            localCache.put(key, product);
            return product;
        }
        
        // 5. 分布式锁（防止击穿）
        String lockKey = "lock:" + key;
        Boolean locked = redisTemplate.opsForValue().setIfAbsent(
            lockKey, "1", 10, TimeUnit.SECONDS
        );
        
        if (Boolean.TRUE.equals(locked)) {
            try {
                // 双重检查
                cached = redisTemplate.opsForValue().get(key);
                if (cached != null) {
                    product = "NULL".equals(cached) ? null : JSON.parseObject(cached, Product.class);
                    if (product != null) {
                        localCache.put(key, product);
                    }
                    return product;
                }
                
                // 查询数据库
                product = productRepository.findById(productId).orElse(null);
                
                // 写入缓存
                if (product != null) {
                    int expire = 3600 + new Random().nextInt(1800);  // 随机过期
                    redisTemplate.opsForValue().set(
                        key,
                        JSON.toJSONString(product),
                        expire, TimeUnit.SECONDS
                    );
                    localCache.put(key, product);
                } else {
                    // 缓存空对象
                    redisTemplate.opsForValue().set(
                        key,
                        "NULL",
                        300, TimeUnit.SECONDS
                    );
                }
                
                return product;
                
            } finally {
                redisTemplate.delete(lockKey);
            }
        } else {
            // 未获取到锁，短暂等待后重试
            try {
                Thread.sleep(50);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
            return getProduct(productId);
        }
    }
}
```

#### 效果

- **正常情况：** 99% 的请求在本地缓存或 Redis 中命中，响应时间 < 5ms
- **缓存穿透：** 布隆过滤器拦截，响应时间 < 1ms
- **缓存击穿：** 互斥锁保护，只有一个请求查数据库
- **缓存雪崩：** 随机过期时间，避免集中失效
- **服务故障：** 熔断降级，返回默认数据

## 🎯 核心要点速记

```
缓存穿透：
- 原因：查询不存在的数据
- 解决：布隆过滤器 + 缓存空对象

缓存雪崩：
- 原因：大量缓存同时过期
- 解决：随机过期时间 + 多级缓存

缓存击穿：
- 原因：热点数据过期
- 解决：互斥锁 / 逻辑过期

服务熔断：
- 目的：防止故障扩散
- 工具：Sentinel / Resilience4j
- 状态：CLOSED → OPEN → HALF_OPEN

最佳实践：
- 多层防护
- 限流降级
- 监控告警
```
